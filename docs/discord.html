Discord and Telegram bots

Discord bot

  • The bot runs inside TGoat: nothing to install or host, no public address needed. One bot serves all your instances, on one server.
  • To set it up, create a Discord application, copy its token, untick Public Bot, paste the token on the Instances page, then invite the bot (steps).
  • Pick its channels with /tgoat channel. Without one, it notifies nothing.
  • Only you, your Discord team and the users you list can command it. Costly commands ask you to confirm.
  • Attack alerts ring your phone. If an instance also has a Discord webhook, turn it off or you get everything twice.

Your own Discord bot lets you follow and command TGoat from your server, with slash commands, buttons and a channel per topic.

Setting it up

You need a Discord account and a server where you may add a bot, such as a new one made with Discord's + button.

  1. Create the application. At discord.com/developers/applications, click New Application. Its name, such as TGoat, becomes the bot's name.
  2. Get the token. On the Bot page, press Reset Token and copy the token, shown only once. It is the bot's password: never share it.
  3. Untick Public Bot on the same page and save, so nobody else can invite your bot.

    If Discord refuses over the default authorization link, set the install link to None on the Installation page, save, and retry.

  4. Give TGoat the token, which it checks with Discord:
    • Web interface: on the Instances page, section Discord bot (optional), paste it in Bot token and click Save the token and turn the bot on.
    • Terminal: at the end of tgoat setup, answer yes to "Follow and command TGoat from a Discord server, with a bot of your own?" and paste it.

    The terminal hides the token and prints its application's name. Stored in secrets.json, the token can be replaced or cleared, but never read back or shown in logs, notifications or the web interface.

  5. Use the invite link: Invite the bot to your server on the Instances page, or the link tgoat setup prints. Pick your server and authorise.

    The link appears once Discord accepts the token. It gives the bot its slash commands and four permissions: view channels, send messages, embed links, read message history (84992).

  6. Answer the server ID question in tgoat setup: press Enter, and the bot takes the only server it is in. The web interface skips it.

Once TGoat runs, type / in your server to see the commands, then set the channels with /tgoat channel. Without one, the bot notifies nothing.

Leave Presence Intent, Server Members Intent and Message Content Intent off: the bot never reads your messages.

How the bot keeps to one server

The bot serves one server, for commands and notifications.

  • With DiscordBot.GuildID empty, it takes the only server it is in and saves that server's ID there.
  • That server then stays. If the bot is no longer in it, it serves none, and the Instances page says so.
  • To fix that, invite the bot back, or empty DiscordBot.GuildID.
  • Invited elsewhere, it ignores that server and warns you, in the log and on the Instances page, to untick Public Bot.
  • In several servers with none saved, it serves none until you set DiscordBot.GuildID.
  • To copy a server ID, turn on Developer Mode (User Settings, Advanced), right-click the server and choose Copy Server ID.

Who may command it

  • You, as the application's owner, or the members of its Discord team who accepted the invitation.
  • Users in DiscordBot.AllowedUserIDs. To get an ID, turn on Developer Mode, right-click the user and choose Copy User ID.
  • Anyone else gets a refusal only they can see, and TGoat logs a warning the first time.

Button clicks are checked like commands. Both work only in your server, never in direct messages or another server.

Other members of your server can read the TGoat channels. If you share the server, keep those channels private.

Channels

Type /tgoat channel in a channel and pick its topic:

  • notifications: every other notification, and the auto-ping;
  • alerts: attack and missile attack alerts, or notifications when unset;
  • logs: forwarded logs, or notifications when unset.

Without notifications, only alerts go out. Without any channel, commands still work but nothing is notified.

The channel must be a text or announcement channel where the bot may view, send messages and embed links. A missing permission is named in the answer.

You can also paste channel IDs in the Discord bot settings. Either way, they are saved in tgoat.json and apply at once.

Public or private answers

Answers are public in a TGoat channel and private elsewhere ("Only you can see this"). A button's answer follows the channel of its message.

For a slow command, Discord first shows the bot thinking. An answer after 15 minutes, or one Discord refuses in the channel, comes by direct message, never in public.

Each Discord user has their own current instance (/instance main) and celestial (/celestial select). The optional instance option of instance commands, with suggestions, targets another instance once.

Buttons and confirmation

These costly or irreversible commands ask first, with Confirm and Cancel buttons: /build, /auction bid, /resources collect-all, /attacks message, /fleet phalanx, /fleet spycrash and /instance disable, which also stops that instance's Defender.

  • The question shows the command, its options, the instance and, for /fleet spycrash, the starting celestial.
  • Confirm runs exactly that, even if you switched account or celestial meanwhile. Nothing runs if the instance was removed or renamed.
  • Only the person who ran the command can answer, within 15 minutes.
  • A TGoat restart loses pending confirmations. The button then says it has expired: run the command again.
  • Defensive fleet moves (deploy, switch, ghost, recall) never ask.
  • A notification button that leads to a costly command, such as Bid minimum, asks too.

Telegram does not ask.

Notifications

Each notification is one message, headed by its instance and coloured by kind (red: attack; orange: missile attack or warning; dark red: error; green: success or sleep mode; blue: auction).

The title says which feature sends it and the kind, such as "Directives · Action completed" or "Defender · Incoming attack". Messages from TGoat itself, such as a settings reload, show the kind alone. The webhook titles its messages the same way.

With DiscordBot.MentionOnAttack (on by default), attack and missile attack alerts mention the application's owners, so their phones ring. Nothing else pings anyone, not even an "@everyone" written in the game.

Some notifications carry buttons:

  • an attack: Attacks (the list of attacks), plus Wake up if the instance sleeps;
  • sleep mode: Wake up while it sleeps, Cancel ghost sleep while a ghost sleep is planned;
  • an auction: Bid minimum.

A button clicked twice or too late gets a plain answer, such as "The bot is already awake."

New notifications: the reviews, a session lost too often, Project Orion, officers and boosters (8)

Three notifications come from the November 2026 reviews, and five more are described below them:

  • Expedition lost (orange): a fleet disappeared before its planned return. "Probably lost" when you may have recalled it yourself in the game.
  • Colonize, once per pass: a new colony (green; choose its lifeform), a colony abandoned, or a zone's try limit reached (orange, with the draws).
  • Offer of the day bought (green): the item and its rarity, and how it was paid. It waits in your inventory, not activated. Another container the game offers right after gets its own message.

Session lost too often (orange, from TGoat itself): after three automatic logins in 30 minutes, TGoat stops logging in until the oldest one is 30 minutes old, and says until when: "The game session was lost 4 times in 30 minutes; TGoat waits until 21:45 before logging in again." It comes once, not for every failed request, and not again for 30 minutes.

If it repeats, open the account in a browser: someone, or another program, may be using it.

Orion reward waiting (orange, from TGoat itself): "An Orion reward is waiting: claim it in the game within the hour." TGoat looks for the mark the game puts on the Orion entry of its menu when a reward can be claimed, on the pages it loads anyway. That mark comes from the game's own script and has not yet been seen on a real Orion page: if TGoat never warns you, check for rewards in the game. It comes once, and again only after the reward has been claimed and a new one waits. TGoat sees it only when it loads a full page, so not at night with Defender.NightWatch on OnAlert, when nothing is loaded. TGoat never claims the reward. Notifications.OrionReward (on by default) turns it off.

Hostile fleet heading for your fleet (red, from the Defender): it gives where the hostile fleet goes and when it arrives, and says "TGoat only protects fleets on your planets and moons." It comes once per event when a hostile fleet aims at something that is none of your planets or moons, such as your fleet at an Orion anomaly: no fleet-save, no alarm. As an attack notice, it mentions you like one.

Officer ending (orange, from TGoat itself): "Your Geologist ends between 23 Nov 14:00 and 24 Nov 14:00. Extend it in the game to keep its bonus." It comes once, when a hired officer may end within Notifications.OfficerEnding hours (48 by default, 0 turns it off), and again after you extend it. The game only shows whole days left, so the end is a range at first and narrows to minutes as the count drops.

Booster about to be lost (orange, from the Boosters): a booster you let TGoat use expires within 12 hours and no planet can take it before then, for example because each one already runs a booster of that kind. It names what holds each planet. It comes once per copy.

Colonize has its own switches: AutoColonize.DiscordWebhook.Active (on by default) and AutoColonize.TelegramMessenger.Active.

Each feature's Notify on Discord switch (such as Defender.DiscordWebhook.Active, on by default) covers both the bot and the instance's webhook.

When Discord is unreachable, a channel is gone or the token is reset (3)

If Discord is unreachable, notifications queue and go out in order, each retried for up to 6 hours before being dropped with a warning. Telegram and the webhook never wait for it.

Notifications for a channel that is gone, or where the bot may not write, are dropped with one warning.

If the token is reset in the Developer Portal while TGoat runs, the bot stops at the first refusal and the Instances page says why. Paste the new token to start it again. A connection lost for more than 5 minutes shows there too, with one warning, and its return is logged.

Logs and auto-ping

DiscordBot.Logging (on by default) forwards warnings and errors to the logs channel, batched every few seconds with repeats grouped, as on Telegram. An attack the Defender logs is skipped when the bot already posts that alert itself, in its alerts or notifications channel.

/logs level shows the Discord level (Warning by default), and /logs set-level changes it until TGoat restarts. Telegram's level is set with /setloglevel.

DiscordBot.AutoPing.Active posts a sign of life in the notifications channel every DiscordBot.AutoPing.EveryHours hours (1 by default), on the hour, like Telegram's: version, uptime and each instance's state. /tgoat autoping and /tgoat autoping-stop start and stop it until the next restart.

/tgoat ping answers "Pong, TGoat 0.1.0-beta.2", so you see the bot is alive and which build runs.

Bot or webhook

Each instance can still post to its own Discord webhook (DiscordWebhook.Url, in secrets.json), copied from a channel's integration settings. A webhook only posts notifications; the bot covers every instance, with commands, buttons, topic channels and logs.

The two are independent. The webhook notifies whenever it is on; the bot, when it is on and has a channel for the notification.

A server that gets both sees everything twice. So setting up the bot, in tgoat setup or on the Instances page, offers to turn off each active webhook; its address stays saved. Keep one that posts elsewhere, such as your alliance's server.

Its settings

They are in the Discord bot part of the TGoat settings (tgoat.json). A new token or server reconnects the bot, and no notification is lost meanwhile; other changes apply at once.

Telegram bot

  • Create a bot with @BotFather in Telegram and paste its token into TGoat.
  • Click Link Telegram, open the link (or scan the code) and tap Start. You never type a chat ID.
  • Only the linked chat can command TGoat. A link works once, for 10 minutes.
  • The same commands as Discord: see Commands.

A Telegram bot of your own lets you follow and command TGoat from your phone. It runs inside TGoat: nothing to install or host.

Setting up Telegram

  1. Create the bot. In Telegram, open @BotFather (the official one, with a blue tick). Its mini app has a button to create a bot. You can also send /newbot: give a name, such as TGoat, then a username that ends in bot, such as my_tgoat_bot.
  2. Copy the token BotFather gives, like 123456789:AAH…. It is the bot's password: never share it.
  3. Give TGoat the token.
    • First run: in Telegram (optional) on the Instances page, paste it in Bot token and click Save the token.
    • Later: in the TGoat settings, group Telegram, turn on Use Telegram, paste the token in Bot token and save.
    • Terminal: tgoat setup asks for it. Press Enter at the chat question.

    The token is kept in secrets.json and never shown again, nor in logs.

  4. Click Link Telegram. It is under the token on the first run, and under Chat ID in the settings. TGoat shows an Open in Telegram button and a QR code for your phone.
  5. Tap Start in the chat with your bot that opens. The bot answers "TGoat is linked to this chat. Send /help to see the commands." and TGoat fills in TelegramMessenger.ChatId for you.
  6. Send /help to see every command.

Until a chat is linked, the bot sends nothing and only waits for its link. A new link replaces the previous one; it expires after 10 minutes, unused or not.

The link opens your private chat with the bot. For a group, add the bot to it and type the group's ID in TelegramMessenger.ChatId yourself. You can always type the chat ID by hand, or an @name for a public channel.

Who may command it

  • Only the linked chat, the one in TelegramMessenger.ChatId, gets answers and notifications.
  • Any other chat is ignored. TGoat logs a warning with that chat's ID and how to link it.
  • Changing chat needs a new link from the web interface. The old chat keeps everything until you tap Start in the new one.

Anyone who has your link in its 10 minutes can link their own chat, so open it yourself and don't pass it on. Only someone signed in to the web interface can make one.

Telegram runs costly commands at once; it does not ask you to confirm like Discord.

Telegram notifications

Each notification starts with the instance, then, when a feature sends it, the feature's name in bold. Each feature has a Notify on Telegram switch, such as Defender.TelegramMessenger.Active.

TelegramMessenger.Logging (on by default) also forwards warnings and errors of the log; /setloglevel changes the level until TGoat restarts. TelegramMessenger.TelegramAutoPing.Active sends a sign of life every few hours.

Telegram settings

They are in the Telegram group of the TGoat settings (tgoat.json). A new token or chat restarts the bot by itself.

When Telegram does not answer

  • "Telegram refused the bot token": the token is wrong or was revoked. Copy it again from @BotFather (its mini app shows it, or send /token), paste it and save.
  • "This link is no longer valid": the link expired, was already used, or a newer one replaced it. Click New link or Link Telegram and tap Start again.
  • The bot answers nothing: you are in another chat than the linked one. The log says "Telegram message from chat N ignored". Link this chat from the web interface.
  • "Telegram Messenger is off" next to Link Telegram: turn on Use Telegram and save the token first.
