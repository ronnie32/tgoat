Get started

  • TGoat is an alpha and bots break OGame's rules: try it on a secondary account, and back up config/ and data/ before each update.
  • Put tgoat in a folder of its own and start it. Coming from TBot 3.6, put it next to your old settings.json first.
  • Open http://localhost:9090 and add your account on the Instances page.
  • If Gameforge asks for a captcha TGoat cannot pass, or for two-factor, sign in with your browser: you pass the check yourself in a window TGoat opens. A session token pasted by hand also works.
  • Every feature starts off. Turn them on one at a time, and watch the Logs before the next.

Before you start: this is an alpha

Warnings

  • Expect bugs. TGoat can crash or do what you did not want. Settings and files may change between builds.
  • Bots break OGame's rules. Gameforge can ban an account that uses one. Try TGoat on a secondary account first. What TGoat does to stay discreet, and what it cannot hide.
  • Its actions in the game are real. A bug can cost you ships or resources.
  • Back up config/ and data/ before you update. Until the first stable release, a new alpha may not convert your old files.
  • The web interface has no password. By default, only your computer can reach it: keep it that way unless you protect it. To reach it from another computer, use an SSH tunnel (how).
  • Never share secrets.json, not even in a bug report. It holds your passwords and tokens.
  • There is no warranty. You use TGoat at your own risk.
  • Its decisions follow the author's understanding of the game. They come from my reading of the rules and of the meta. I did my best, but I cannot promise that every decision is optimal or fits every situation; the settings let you change what does not suit you.

Reporting a problem

Send your report to whoever gave you this build, without anything private. Include:

  • what you did and expected, step by step;
  • the line printed by tgoat version;
  • the relevant lines from log/, with their time.

Install and first run

TGoat is a single file: tgoat.exe on Windows, tgoat elsewhere.

  1. Put it in a folder of its own.
  2. Start it. It creates config/, data/ and log/ next to itself.

Coming from TBot 3.6? Before the first start, put tgoat next to your old settings.json. TGoat imports it, and features that were on in TBot stay on.

Add your account

Imported TBot accounts are already there. Otherwise:

  1. Open http://localhost:9090. The first time, it shows Add an account on the Instances page.
  2. Fill in Name of the instance and Community (en, fr…).
  3. Give your Gameforge E-mail and Password, or click Sign in with your browser (how). A session token works too.
  4. Click Test the login. TGoat lists your players by universe.
  5. Pick the universe, then click Create the instance. It connects with every feature off.

First run describes the other fields and the optional Telegram and Discord bot. In a terminal, tgoat setup asks the same questions.

Log in

TGoat tries a session token you just gave it, then the session saved at the last login, then your e-mail and password. That session survives restarts.

TGoat never signs out of the lobby, so your browser stays signed in.

Sign in with your browser

TGoat opens a browser window on the Gameforge login. You sign in and pass any check yourself, so a captcha or two-factor is no problem. TGoat keeps the session token and closes the window.

  1. In Settings, open Account and click Sign in with your browser. In Add an account, the button sits under Session token. An instance whose login failed has the same button on its card in Instances. In a terminal, run tgoat login, or tgoat setup and pick 3 (offered when TGoat finds a browser).
  2. Sign in to Gameforge in the window that opens.
  3. The window closes. The panel says "Gameforge session token stored. The instance connects with it now." (for a disabled instance: "The instance uses it once you enable it."). tgoat login prints "Gameforge session token stored for", the account and "from a browser sign-in". In Add an account, the panel says "Signed in to Gameforge" and the token is used when you test the login or create the instance.

TGoat waits up to 10 minutes, then closes the window. Cancel (Ctrl+C in a terminal) closes it too, which can take a few seconds. Nothing is read from your everyday browser, and the window leaves no profile behind.

On a running instance, Settings asks before it starts: the new token logs the instance out and in again, which Gameforge sees as a new login.

The window goes through the account's proxy, if it has one. The sign-in is tied to that proxy and to the lobby. In Add an account, the lobby and proxy fields are locked while a sign-in runs or its token is held: cancel it to change them. In Settings, if either changes before you finish, nothing is stored and you sign in again.

LoginBrowser (see the new settings) picks the browser. With Auto, it is your default browser when that is Chrome, Edge, Brave, Chromium or Opera, else the first of them installed. TGoat uses Firefox (version 128 or later) only when none is installed, and warns you: Firefox tells the page it is remote-controlled, so Gameforge may treat the sign-in as automated.

The window opens on the computer that runs TGoat, which needs a screen. While you sign in, another user logged in to that computer could read the session token: use it on a computer only you use. On a server, see below.

TGoat on another computer (VPS)

When TGoat runs on a server, the browser still opens on your own computer. The sign-in leaves from the server and its proxy, so Gameforge sees the server's address.

  1. On your computer, open an SSH tunnel to the web interface: ssh -N -L 9090:127.0.0.1:9090 you@your-server (use the port of WebUI.Urls in place of the second 9090).
  2. Open http://localhost:9090 and click Sign in from another computer (Settings, Account, or Add an account).
  3. The page shows a command such as tgoat login --to "http://localhost:9090" --code K7P2-9QXM --instance MAIN, with a Copy button. Run it on your computer, quotes included. It is the same tgoat program, with no setup. It uses your LoginBrowser setting if this computer has a TGoat folder, else Auto.
  4. Sign in in the window that opens. It waits about 9 minutes. The token goes to the server.

The code lasts 10 minutes and is for one account. A new code or a new sign-in for the same account cancels the previous one. Once tgoat login has accepted the code, it is used up: if the sign-in then fails or you cancel, the command says "The code is now used" and you create a new one. The window closes 45 seconds before the code would end, so the token has time to arrive.

Before it takes the code, tgoat login checks the address and finds a browser, so a typo or a missing browser does not use the code up. A computer with no screen is refused there too.

The web interface must be on (not --console). A reverse proxy that drops CONNECT requests does not work: after it accepts the code, tgoat login says the sign-in tunnel "does not get through" and opens no browser. Create a new code and use the SSH tunnel. An http:// address other than localhost or 127.0.0.1 sends the code and the token in clear text: tgoat login warns and prints the SSH command to use.

Reaching TGoat by a name, or behind a reverse proxy

TGoat answers only requests for localhost, an IP address, a name in WebUI.Urls or WebUI.GameProxyUrls, or a name in WebUI.AllowedHosts. Any other name gets a 403 unknown_host. This stops a web page from taking over the interface.

  • If you opened TGoat by a name yourself, such as http://mypc:9090, add mypc to WebUI.AllowedHosts in tgoat.json and restart TGoat. Write host names only, separated by commas: no http://, no port.
  • If the 403 names a host you never typed, do not add it. A web page tried to use TGoat.
  • Behind a reverse proxy, list its public name and let it keep the browser's Host. Caddy does by default; in nginx, set proxy_set_header Host $host;.
  • nginx's default sends Host: 127.0.0.1:<port>, which TGoat always accepts, so it cannot see the browser's name. The proxy must then answer only for its own name (server_name, and a default_server that refuses other names). The same holds for a proxy that rewrites Host to localhost or an IP.
  • For the command to carry the public address, the proxy should send X-Forwarded-Host (a name TGoat accepts, such as one in WebUI.AllowedHosts) and X-Forwarded-Proto: https. Otherwise the command shows the address TGoat received.

Session token

If the browser sign-in is not possible, paste a session token by hand. It also keeps your password out of TGoat.

  1. In your browser, sign in at lobby.ogame.gameforge.com.
  2. Press F12 to open the developer tools.
  3. Open the cookies: in Chrome or Edge, tab Application, then Cookies; in Firefox, tab Storage, then Cookies.
  4. Select https://lobby.ogame.gameforge.com.
  5. Copy the value of the cookie gf-token-production, without its name.
  6. Paste it in Session token (Add an account), Gameforge session token (Settings, Account), or tgoat setup.
  7. Click Test the login. It says "Gameforge accepted the session token."
  8. Create the instance, or save the settings.

The setting is Credentials.GameforgeToken. Telegram and Discord refuse it: a chat keeps what you send.

With a token, the e-mail and password are optional. If Gameforge refuses the token, TGoat asks you for a new one. Meanwhile it uses the e-mail and password, if set, or waits.

Signing out of the lobby in your browser ends the session TGoat uses.

Captcha and two-factor

  • Image puzzle (gf-image-drop-captcha): TGoat solves it. With General.CaptchaAPIKey set, it asks the obot service first.
  • gf-pow-captcha: TGoat will never solve it, so sign in with your browser. It retries after 30 minutes to 2 hours.
  • Two-factor authentication: no setting yet. Sign in with your browser, where you answer it yourself.
When the login fails

After a wrong e-mail or password, refused token, two-factor, unknown universe, blocked player, vacation mode or unusable proxy, the instance waits. Any settings change restarts it at once.

TGoat retries by itself, with a growing delay, after a network error, Gameforge being down, an unsolved captcha or a refused IP.

Turn on a first feature

Turn features on one at a time, in the web interface (see its tour):

  1. Wait until the Instances page shows your instance as Running.
  2. Open Settings and pick the instance.
  3. Turn on the switch in a feature's section title, such as Watch for attacks for the Defender.
  4. Click Save 1 change.
  5. Watch the Logs and the Command deck. Turn on the next feature only when the bot does what you expect.

Before you play by hand, turn on Manual mode in the OGame page so the bot pauses.

Let the setup assistant suggest settings

Once TGoat has read your account, the Map shows a banner that opens the setup assistant. It asks a few questions, pre-filled from your account, then proposes settings grouped by theme that you apply or skip. It is most useful when your account has already grown.

It never changes a value you set yourself unless you ask, and every change it makes can be restored from the settings history. You can open it again at any time from the Settings page or the command palette (Ctrl K).

Updates

TGoat looks for a new version on GitHub, in the releases of ronnie32/tgoat, a few minutes after it starts and then about every 6 hours. It connects to github.com directly, never through an account's proxy, and sends nothing about you or your accounts. If a check fails, the log says so once and TGoat tries again at the next one.

In the TGoat settings (tgoat.json), Update.Mode chooses what happens:

  • Notify (the default): TGoat tells you once about each new version, in the web interface, on Telegram and on Discord. A banner at the top of every page links to the release notes and has an Install button.
  • Install: TGoat installs each new version by itself.
  • Never: TGoat never contacts GitHub.

Update.Channel chooses the versions: Alpha follows every version, test versions included, and Stable only the stable ones. An alpha build follows Alpha unless you change it.

During the alpha, keep Notify, and back up config/ and data/ before you click Install: an alpha may change your files.

How an update installs

  1. TGoat downloads the new version and checks it (see below).
  2. It waits for a quiet moment: no attack being handled, no fleet-save planned or flying, no ghost sleep planned, no fleet being sent, no sign-in in progress, no manual mode and no sleep you asked for. The banner says what it is waiting for and has a Cancel button.
  3. Just before it restarts, it checks the settings and the release on GitHub again. Setting Update.Mode to Never, or to Notify for an install that Install mode started, stops it; so does a release the owner has withdrawn.
  4. It renames itself tgoat.exe.old (tgoat.old on Linux and macOS), puts the new version in its place and restarts with the same options.

If no quiet moment comes for 24 hours, TGoat gives up, tells you what held it, and installs that version only when you click Install. The same goes for an install you cancel. If TGoat cannot write in its own folder (Program Files, /usr/local/bin), Install mode works like Notify and tells you to update by hand.

If a download fails or an antivirus holds a file, Install mode tries again at the next check; after a click, click Install again. If TGoat cannot put its own program back after a failed update, it tells you which file to rename, and installs nothing more until you have renamed it and restarted TGoat.

The new version is kept once it has run 2 minutes with its instances started. TGoat then deletes the .old file and tells you. If the new version fails to start twice in a row, the next start puts the previous one back and tells you; a start stopped by you, or by a second TGoat already using the configuration folder, does not count. If an antivirus stops that, TGoat says so and tries again at the next start; until then, it installs no update, not even from the Install button. If the new version cannot even be launched, the previous one comes back at once. TGoat then never installs that version by itself; the Install button still can.

Run one TGoat per program file: a second TGoat started from the same file never updates.

On Linux and macOS, TGoat restarts in the same process, so this works in a terminal, under systemd and in a container. On Windows, it starts the new version in the same console, then exits: your prompt comes back while TGoat keeps writing. If a service manager runs TGoat on Windows (NSSM, WinSW) or should do the restart itself, set the environment variable TGOAT_SERVICE=1: after an update, TGoat exits with code 75 and the manager must start it again. TGoat warns at start when NSSM or WinSW runs it without that variable.

How trust works

Each release has a checksums.txt file with the SHA-256 of every archive, signed with the TGoat release key. TGoat installs a version only if:

  • the signature matches the public key built into TGoat;
  • the archive has the checksum that the signed list gives;
  • the version is newer than the one running (never an older one);
  • the new program starts and gives that version.

If anything else happens, nothing is installed. TGoat takes the highest release that passes these checks, so a broken newer one does not hide it, even after a restart. A release that is not signed with that key, or whose signed list belongs to another version, may come from someone who took over the GitHub account: TGoat only says "A release that could not be verified appeared on the TGoat GitHub page: do not install it by hand", never its name or a link. Do not download it. A signed release with no download for your system is mentioned once, and nothing is installed; if its download is only missing from the page (still uploading), TGoat looks again at each check. TGoat's update notices are plain text, shown as written on Telegram and Discord, with no link preview.

Check a release by hand

tgoat version prints the fingerprint of the release key built into your TGoat. It must be:

Release key SHA-256: 9918d9c3ebba3283d19cc048395047f11f24756c6a1ea0abfebd63236b68dfdf

The release public key:

-----BEGIN PUBLIC KEY-----
MCowBQYDK2VwAyEAJqTZcwxwgqfnDlIxRMFkuQUjV943CFRAdmui/BHT66U=
-----END PUBLIC KEY-----

Save it as tgoat-release.pub, download the archive, checksums.txt and checksums.txt.sig, then run (OpenSSL 3; the one in Git for Windows works):

openssl pkey -pubin -in tgoat-release.pub -outform DER -out tgoat-release.der
sha256sum tgoat-release.der
base64 -d checksums.txt.sig > checksums.sig.bin
openssl pkeyutl -verify -pubin -inkey tgoat-release.pub -rawin -in checksums.txt -sigfile checksums.sig.bin
sha256sum --ignore-missing -c checksums.txt

The second command gives the fingerprint above, the fourth prints Signature Verified Successfully and the last OK for your archive. On macOS, use shasum -a 256. On Windows, Get-FileHash tgoat-release.der gives the fingerprint, certutil -decode checksums.txt.sig checksums.sig.bin replaces the third command and Get-FileHash gives an archive's SHA-256.

Roll back by hand

  1. Stop TGoat.
  2. If tgoat.exe.old is still there, delete tgoat.exe and rename tgoat.exe.old to tgoat.exe. Otherwise, download the version you want from the releases page.
  3. Set Update.Mode to Notify or Never, so the newer version is not installed again.
  4. Start TGoat.
